# 2026-11-28 小程序运行回归

## 修复与根因

| 现象 | 根因与处理 |
| --- | --- |
| `GET /actuator/health` 被拒绝 | 复现时 8080、6380 和 5010 均未监听，重启前未发现端口冲突。旧日志没有记录退出原因。原启动器等待 Spring 健康，但语音启动只是异步发起。本机启动现在等待 Whisper、Spring 整体健康和就绪状态、语音代理，再发布设备地址。停止脚本按项目可执行路径识别 Redis，并记录 Windows venv 中实际监听的语音进程。前端给拒绝连接单独的提示。 |
| 六个组件 WXSS 警告 | 设置项、空状态和数字人图标使用标签后代选择器，标题波形使用标签及位置选择器，导航使用标签与 hidden 属性选择器，聊天发送键使用标签和 disabled/loading 属性选择器。改用 WXML 类名、组件状态和样式类。沿用组件隔离、原图标资源与发送箭头中心定位。 |
| 录音静音被报为 502 | 模拟器录制并上传的文件触发 Whisper 无有效语音，工作进程返回 422，Java 代理此前统一映射 502。现在保留 422 及提示，真实上游异常仍返回 502。 |
| 视觉测试在 Windows 中文目录失败 | OpenCV 无法从含中文的绝对路径加载 ONNX。由 Python 读取文件，将原模型的字节传给 OpenCV；健康及无效图片测试通过。 |
| 文本 selectable 弃用提示 | 聊天消息改用 `user-select`，保留长按选择。 |

生产与本机开发是两套启动方式。旧项目 `start.ps1` 使用 MySQL、Redis 和筛查服务，并按配置联动 RabbitMQ 及向量组件。当前 `start-local.cmd` 使用项目原有的 local-native 配置（H2、Redis、独立语音工作进程）。本次未改变该配置的健康范围和正式部署定义。数据库通过真实注册、登录、上传、查询、下载和删除回归；完整异步筛查和报告需要正式依赖。

## 保留的运行提示

- `WeChatLib 3.18.1` 为当前 IDE 选定的灰度基础库。项目无已声明的全功能最低库版本。官方接口定义中，`getRecorderManager` 从 1.6.0、`onKeyboardHeightChange` 从 2.7.0、`getDeviceInfo/getWindowInfo` 从 2.20.1、`requirePrivacyAuthorize` 从 2.32.3 提供。后者与部分设备、键盘和录音事件均有能力检测，按完整隐私授权路径验证至少使用 2.32.3。实测 3.18.1 上的异常均定位到服务、WXSS 或运行环境，因此保留当前调试版本。 [微信小程序官方接口定义](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)
- 域名、TLS 和证书提示来自已有的本机私有工具配置，用于 HTTP 局域网联调。共享配置仍有 `urlCheck: true`，启动器不再改写开发者工具私有配置。模拟器走 127.0.0.1，真机由启动器获取电脑的 WLAN IPv4。非模拟器的回环地址有显式提示。
- `WAServiceMainContext.js`、`WAAutoService.js` 由 IDE 通过临时调试端口的 `__dev__` 路径注入。录音格式提示、HarmonyOS 平台提醒和 worker 上报能力提示也来自运行环境。项目只区分 DevTools 和实际设备，设备录音走 WAV，模拟器 WebM 仍走原已适配的转写分支。
- MCP 端点响应 `mcp_token_required`，当前 Codex 会话未注册相应凭据；使用官方编译器、CLI、IDE 界面和控制台取证。工具内部文件未修改。真机调试面板的 81 条打包提示来自已有的 packOptions 排除项，展开可见设计素材及开发文档未打包。
